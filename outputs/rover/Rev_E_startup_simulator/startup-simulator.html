Rev F candidate · Separate charge and discharge paths

Try Insert cell → Wake → Arm motors → Trip load fault → Connect USB. The model keeps USB programming and the charge path available while the battery-to-load path is open. Trip represents an assumed hardware trip, and the wake event assumes the protector accepted the request.

This logic check assumes a functioning one-way charge branch, a hardware USB inhibit on the discharge switch and a fault latch that persists across USB changes. It excludes diode leakage, switching timing, cold power-on reset, shorts on the protected pack node itself, and actual charge acceptance.

Rev F fixture · Hardware rearm latch

Hold the arm button while reset is active, then release reset. The drive switch stays off until the button is released and pressed again.

These inputs represent the signals at the flip-flop after filtering. Button bounce, brownout detection and real hardware timing are outside this model.

Model boundaries

Each click evaluates a steady-state condition. In shutdown, the assumed USB contribution at PACK is charger BAT voltage minus the configured path drop. In normal operation PACK is approximated by cell voltage. A cleared fault is modeled with PACK pulled toward the cell by the protector's recovery circuit. “Trip discharge fault” imposes a persistent short. Restoring the real sense path under that short models an eventual retrip.

This model excludes MOSFET dynamics, charger startup, threshold tolerance distributions, fault timing, and actual short-circuit current. It does not qualify a wake fixture or predict bench waveforms.
